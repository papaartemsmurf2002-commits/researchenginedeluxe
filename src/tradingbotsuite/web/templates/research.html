Research

Research is an offline evidence workspace. It collects provider data, builds fixture packs, materializes features, tests strategies and exits, ranks candidates, and blocks weak evidence before anything can reach promotion review.

Optimizer And Gates

Legacy V2 Model Workflow

1. Build Dataset
Reads persisted BTC signals, reconstructs signal-time features, applies the same triple-barrier math used live, and writes a parquet dataset plus manifest.
2. Train Model
Fits the baseline logistic-regression model on the dataset. This is still offline only and does not change live behavior.
3. Calibrate
Applies isotonic calibration when the sample is large enough, or a safer fallback when it is not.
4. Replay Evaluate
Runs walk-forward out-of-sample checks and compares V2 against the current V1 baseline before any promotion is even considered.

Before You Build

You need persisted BTC signal history in SQLite. No signals means no dataset.
The builder reconstructs signal-time context, not just raw price rows. It uses stored signals plus Binance history.
Missing additive features such as funding or open interest do not get fabricated. They become explicit missingness flags.
A good dataset is not just “finished”. Check row count, class balance, and missing-feature rates before training.

How Dataset Build Works

Inputs

Stored BTC signals, Binance 15m history, and any available signal-time context already saved in decision packets.

Processing

The builder preloads one shared bar range, slices it locally per signal, rebuilds features, freezes ATR barriers, and labels outcomes with the same exit logic used live.

Outputs

A parquet dataset for training plus a manifest with row count, dataset hash, config snapshot, and missing-feature rates.

Quality Check

Do not move to training blindly. First confirm the dataset is large enough, not one-sided, and not dominated by missing features.
