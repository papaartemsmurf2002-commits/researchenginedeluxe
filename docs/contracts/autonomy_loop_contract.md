# Autonomy Loop Contract

Status: v2 dry-run contract
Audit ID: `V2-AUD-AUTONOMY-001`

The autonomy loop is a research-only orchestration surface for proving that v2
components can be wired together without weakening evidence rules. The dry-run
implementation is fixture-backed and `sandbox_diagnostic` only.

## Schemas

- `AutonomyDryRunConfig`
- `AutonomyStepResult`
- `AutonomyBlockerReport`
- `AutonomyDryRunManifest`
- `AutonomyDryRunResult`

## Required Loop

The dry-run loop must execute, or explicitly block, these steps:

1. Universe fixture creation.
2. Archive fixture manifest creation.
3. Coverage and quality fixture manifest creation.
4. Backtest-data preflight when the archive-backed data mode is used.
5. Declarative strategy spec validation.
6. Vectorized backtest and run artifact creation.
7. Append-only ledger logging.
8. Non-promotable Lead Book update.
9. Blocker report creation.

## Data Modes

- `archive_fixture` is the default. It creates a local archive root under the
  requested output root, writes silver bars through the archive writer, appends
  a coverage report, creates an archive snapshot, refreshes a fixture
  Hyperliquid as-of universe, and loads the backtest panel through
  `BacktestDataService`.
- `manifest_fixture` preserves the original compact WPR106-422 behavior for
  compatibility and writes JSON fixture manifests without using the archive
  service path.

## Required Evidence Fields

- `research_only=true`
- `observe_only=true`
- `promotion_ready=false`
- `candidate_evidence=false`
- `candidate_pack_eligible=false`
- `live_signal=false`
- `paper_signal=false`
- `sizing_instruction=false`
- `order_placement_instruction=false`
- `runtime_mode_change=false`
- `evidence_mode=sandbox_diagnostic`
- Backtest window starts on or after 2024-01-01.
- Backtest window spans at least six usable months.
- Coverage floor is 0.98 or stricter.
- Universe mode is `as_of`.
- Archive-backed dry-runs write the backtest-data manifest as
  `sandbox_diagnostic`.
- Ledger rows generated by this loop are sandbox diagnostic.
- Lead Book rows generated by this loop are non-promotable and carry missing
  real-evidence blockers.

## Forbidden

- Calling venue APIs or collectors directly from the dry-run.
- Writing committed generated research evidence.
- Marking fixture output as accepted research evidence.
- Producing candidate packs, paper signals, live signals, sizing instructions,
  order-placement instructions, runtime-mode changes, or promotion-ready
  artifacts.
- Suppressing blockers for missing real Hyperliquid archive/coverage evidence.

## Acceptance

A dry-run is accepted as an operational wiring check only when it writes an
`autonomy_manifest.json`, a `blocker_report.json`, a local append-only ledger,
and a non-promotable Lead Book row under the requested output root. It is never
accepted as strategy performance evidence.
