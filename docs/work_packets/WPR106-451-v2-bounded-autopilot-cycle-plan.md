## Objective

Add a bounded research-cycle planning/enqueue surface that lets the manager
agent declare an ordered durable v2 loop, optionally enqueue the declared worker
jobs, and automatically append a final `audit_check` job that verifies required
successful job kinds, required artifact refs, and declared loop order.

This is a scheduler-adjacent control surface only. It must not run jobs, call
venue APIs, stream WebSockets, certify historical coverage, mark accepted
research readiness, or create paper/live/order/sizing/runtime/promotion output.

## Acceptance Criteria

- A bounded cycle spec can be loaded, validated, written as a plan manifest, and
  left plan-only without mutating the job store.
- With explicit enqueue enabled, the declared worker jobs are enqueued in order
  and a generated `audit_check` job is appended with target job IDs, required
  successful job kinds, required artifact ref prefixes, and required job-kind
  order.
- The planner rejects unsupported worker kinds, user-supplied `audit_check`
  jobs, boundary override keys, unsafe run IDs, and cycle sizes above the
  configured cap before enqueueing.
- The generated manifest and CLI output preserve the full research-only
  invariant and explicitly keep `accepted_research_ready=false`.
- No job execution, venue fetch, WebSocket stream, accepted coverage proof,
  candidate pack, paper/live signal, order placement, sizing instruction,
  runtime-mode change, or promotion behavior is added.

## Decisions Made

- Added `redx autopilot research-cycle --mode bounded` as a
  plan/enqueue-only surface instead of a job runner, scheduler daemon, or
  stream process.
- Required a bounded cycle spec to declare universe refresh, at least one
  collector/archive stage, coverage audit, vectorized backtest, ledger append,
  and Lead Book upsert before any optional enqueue.
- Made the final `audit_check` job generated by the planner, not user-supplied,
  so target job IDs, required successful kinds, artifact-prefix checks, and
  ordering checks are derived from the accepted plan.
- Rejected unsupported worker kinds, boundary override keys, duplicate job IDs,
  unsafe run IDs, audit report path escapes, and job counts above `max_jobs`
  before enqueueing.
- Kept plan manifests `research_only`, `observe_only`,
  `accepted_research_ready=false`, and `promotion_ready=false`.
